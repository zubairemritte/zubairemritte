# Comprendre et entretenir mon profil GitHub

## Le rôle de ce dépôt

Le dépôt `zubairemritte/zubairemritte` porte le même nom que le compte GitHub. Son fichier `README.md` sert de présentation sur le profil. C'est la page d'entrée : elle explique le parcours, oriente vers les projets et permet de prendre contact.

Le code de CareerGraph Europe appartient à son dépôt dédié. Les quatre autres projets auront aussi leurs propres dépôts lors de leur démarrage. Les fiches présentes ici servent à préparer et expliquer leurs objectifs.

## Pourquoi cette présentation

1. **La bannière** donne une identité visuelle commune : fond bleu nuit, textes clairs, accent vert et formes géométriques originales.
2. **L'introduction** explique le lien entre économie, analyse des données et décisions métier.
3. **Les expériences** donnent immédiatement des éléments concrets : causalité et monitoring chez Carrefour, contrôles financiers chez Esya Conseil, BI et automatisation chez Checkout.
4. **Les cinq projets** présentent les objectifs futurs et permettent d'ouvrir leurs fiches détaillées.
5. **Les compétences** distinguent le socle déjà utilisé des outils à approfondir pendant les projets.
6. **Les contacts** permettent au lecteur de passer de la consultation à un échange.

Le profil anglais répond à la cible internationale ; la version française facilite la lecture et l'apprentissage. Les résultats, démonstrations et captures des futurs projets seront ajoutés au fur et à mesure de leur validation.

## Les fichiers, simplement

| Fichier ou dossier | Utilité | Quand le modifier |
| --- | --- | --- |
| `README.md` | Présentation principale en anglais | Parcours, contact, projet livré ou nouveau résultat |
| `assets/hero.svg` | Bannière large | Changement d'identité visuelle ou de positionnement |

| `docs/projects/*.md` | Cadrage détaillé de chaque projet | Lorsqu'une décision de conception est validée |

**README** : fichier de présentation et de prise en main.  
**Dépôt** : espace GitHub contenant les fichiers et leur historique.  
**Commit** : enregistrement d'un ensemble cohérent de modifications.  
**Branche** : ligne de travail permettant de préparer des changements.  
**SVG** : image vectorielle stockée sous forme de texte, nette à plusieurs tailles.  
**CI** : vérifications automatiques déclenchées lors des changements de code.

## Ce qui est prêt et ce qui vient ensuite

Cette étape prépare la présentation, les visuels et les cinq cadrages. Le README doit indiquer l'état réel de chaque produit. Les fonctionnalités prévues ne deviennent pas des réalisations simplement parce qu'elles sont décrites.

Le premier travail de développement prévu est **CareerGraph Europe** : vérifier les sources et leur accès, relire le starter, puis construire une première chaîne de données testable. Les choix d'infrastructure seront faits en fonction de cette première chaîne et des contraintes réelles.

## Mettre à jour une information

Sur GitHub, ouvrir le fichier concerné, utiliser l'édition, puis vérifier l'aperçu avant d'enregistrer un commit avec un message clair. Exemple : `docs: add verified CareerGraph demo and evaluation results`.

Pour un projet livré, mettre à jour ensemble : son statut, son lien, sa fiche, sa carte visuelle si nécessaire, la version française et la feuille de route. Ajouter uniquement des captures de l'application réelle et des chiffres accompagnés de leur contexte.

Les SVG sont éditables avec un éditeur de texte ou un logiciel vectoriel. Ils ne chargent ni police, ni script, ni image externe. Les libellés essentiels sont aussi présents en texte dans le README pour rester lisibles et accessibles.
